# 023-03 — Lexer
**Epic:** 023-DSL-compiler-front-end · **Effort:** S · **Depends on:** 023-01, 023-02

## Context
- Part of `hadronyche-dsl/syntax/` (lexer, parser, AST, source spans, diagnostics).
- The concrete syntax was chosen in 023-01; this ticket implements its token set. If 023-01 chose the Rust-macro form, the lexer is a token-tree adaptor over `proc_macro2` tokens producing the same token stream with spans.
- Lexical items needed by the language: identifiers, keywords (including the edge-module marker, the gap-override and the join opt-out constructs of 023-01), integer and float literals, fixed-point literals (Q1.31 and Q0.32), rate literals (for device-facing ports of edge modules, e.g. 48 kHz; network ports are always at 96 kHz, C-01), punctuation, comments.
- The parser (and therefore the lexer) is fuzzed with zero panics and zero hangs (023-AC-9; done in 023-05).

## Work
1. Implement `syntax::lexer::lex(source: &str) -> Result<Vec<Token>, Vec<Diagnostic>>`; every token carries a `Span`.
2. Report invalid characters, unterminated comments and out-of-range literals as diagnostics with codes from 023-02, never panics.
3. Comments and whitespace are discarded (needed so classification is stable under reformatting, 023-AC-5).

## Acceptance criteria
1. Unit tests cover every token kind of the 023-01 grammar outline, each asserting its kind and span.
2. Two sources differing only in whitespace and comments produce identical token-kind sequences.
3. An invalid character yields exactly 1 diagnostic whose span covers that character.
4. The lexer runs in time linear in input size (test: 1 MiB of a repeated token lexes in under 1 s in CI).

## Definition of done
- [ ] Tests green in CI, unprivileged
- [ ] Every parser touched is fuzzed (fuzz target added in 023-05)

## Out of scope
- Parsing and AST (023-04), fuzzing harness (023-05).
