# 025a-09 — Exact-class conformance vectors
**Epic:** 025a-DSL-conformance-corpus-probe-and-reference-programs · **Effort:** S · **Depends on:** 025a-05, 025a-06, epic 007, epic 024
## Context
Exact verification tier `[decision]`: exact-class modules produce identical bits. Mechanism: record input slices and output hashes; replay the same generated code; compare.

`hadronyche-dsl/conformance/vectors/` holds, **per exact-class program** of the corpus: input slices and expected output hashes, **generated by the compiler (epic 024) and checked in**. The file format is the conformance vector format of epic 007.

Determinism classes: `exact-fixed` — bit-exact everywhere, including host to device; `exact-float` — bit-exact only where the startup fingerprint matches. The DSL has no non-deterministic node in v1, so every accepted positive corpus program is exact-class and gets a vector file; `bounded` arises only at run time from a fingerprint mismatch, or for hand-written modules (C-123).

Constants: domain rate 96 kHz (C-01); slice = 48 frames = 0.5 ms (C-02); 4-byte samples (C-03); 6 channels per stream, 192 bytes per channel per slice, 1 152 bytes of audio, no per-channel id byte (C-04). Fuzz budget: 60 s on every change and 1 hour nightly, corpus kept (C-95).
## Work
1. A generator command (e.g. `cargo run -p hadronyche-dsl --bin gen-vectors`) that, for every positive corpus program, produces deterministic input slices (fixed seed), runs the generated module, and writes inputs plus output hashes in the epic 007 vector format.
2. Check the generated vectors into `vectors/`.
3. A host runner test that loads each vector, runs the generated module, hashes outputs and compares slice by slice, reporting the first differing slice and output.
4. A check that every positive corpus program has a vector file and no vector file is orphaned.
5. If the vector reader is new code (not reused from epic 007), add a fuzz target for it.
## Acceptance criteria
1. Every positive corpus program has a checked-in vector file; the coverage check passes.
2. The host runner passes on all vectors.
3. Flipping one bit of one expected hash makes the runner fail naming the program, slice index and output.
4. Running the generator twice produces byte-identical files.
5. If a fuzz target is added, it runs 60 s on every change and 1 hour nightly without a crash (C-95).
