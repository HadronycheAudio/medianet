# 024b-14 — Fuzz manifest and vectors decoders
**Epic:** 024b-DSL-code-generator · **Effort:** S · **Depends on:** 024b-12

## Context
Definition-of-done rule of the epic: "Every parser touched is fuzzed." This epic adds decoders for the binary manifest and the vectors file written by `hadronyche-dsl build <source> --out <dir>` (024b-12). These files are later read by the conformance suite (epic 025) and the embedded device (epic 026).

## Work
- Fuzz targets, with a tool of the implementing team's choice (C-192), for: binary manifest decoder, vectors file decoder, readable manifest parser if it is a custom parser.
- Seed corpora from the files generated by the 024b-12 test programs.
- CI runs each target for 60 s on every change and for 1 hour nightly, unprivileged; the corpus is kept between runs (C-95); crashes fail the job.
- Fix any crash found; decoders return named errors, never panic.

## Acceptance criteria
1. One fuzz target per decoder exists and runs in CI 60 s on every change and 1 hour nightly without a crash; the kept corpus grows across runs (C-95).
2. Truncated, oversized-length and wrong-magic inputs return named errors (unit tests derived from fuzz findings).
3. Decoders do not panic on any input (fuzz target asserts no panic).

## Definition of done
- [ ] Tests green in CI, unprivileged
- [ ] Every parser touched is fuzzed
- [ ] Every new factual claim carries an evidence tag

## Out of scope
- Fuzzing the DSL source parser (epic 023).
