# 026b-09 — Exact-fixed replay on device
**Epic:** 026b-Reference-device-and-porting-guide · **Effort:** S · **Depends on:** 026b-03, epic 024, epic 025

## Context

Module code on the device is generated by the DSL compiler (epic 024): one `no_std` process function, no allocation, state and stack sizes as constants, kit arithmetic only. Exactness between host and device is promised **only for the exact-fixed class** `[decision]`. The DSL has no non-deterministic node in v1; the bounded class arises only from an exact-float fingerprint mismatch or from hand-written modules that do not claim exactness (C-123).

On hosted, record and replay of exact-class modules is a runtime feature; on the device it is **done on a host**: the same generated `no_std` code is rerun against captured input `[decision]`. Epic 025 verifies host-to-device exactness for exact-fixed.

Epic criterion 026-AC-6 (Exactness): an exact-fixed DSL module produces on the device the same output hashes as on the host, by replay of captured input.

## Work

1. Pick one exact-fixed DSL module (e.g. a fixed-point gain/mix), generate its `no_std` code with the epic-024 compiler, and link it into the reference firmware on the sink path.
2. Capture its input on the device (or feed a known capture) and hash its output per slice on the device; publish/collect the hashes.
3. On a host, rerun the same generated code against the captured input; compute the same hashes.
4. Compare; store the result in `doc/design/reports/` (C-130).

## Acceptance criteria

1. For at least 10 s of input (20 000 slices), device and host output hashes are identical for every slice.
2. The module is exact-fixed class (compiler reports the class).
3. Firmware with the module still passes the no-alloc / no-libm symbol check.

## Definition of done

- [ ] Tests green in CI, unprivileged
- [ ] Every new factual claim carries an evidence tag
- [ ] The crate builds for at least one device target and for the host (for tests) in CI

## Out of scope

- Non-exact classes (no exactness promised).
- The DSL compiler itself (epic 024) and general exactness verification (epic 025).
- The device's calibration factor (026b-19), which reuses the module linked here.
