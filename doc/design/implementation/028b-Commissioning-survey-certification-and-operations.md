# 028b — Commissioning survey, certification and operations

**Phase:** P7 · **Scope:** L (24 tickets, about 31.5 days) · **Depends on:** 008a, 012, 013, 015, 019, 020, 021, 022, 027, 028a · **Blocks:** none

## Goal

Complete the operator-facing tool (`hadronyche-commission`) with everything that needs a running medianet, and write the checklists and guide, so that a set of machines and a switch become a **commissioned medianet**: the tool measures what must be measured on site, proposes the numbers the operator must choose, and certifies what can be certified. Everything the runtime deliberately does *not* compute at run time lives in the tool. Epic 028a has already delivered the binary skeleton, the configuration format, the capacity arithmetic, the offline `validate` command, the A proposal computation and the buffer-memory check; this part fills in the online subcommands (`survey`, `window`, `propose-a` with its `--apply` option, `certify-sink`, `certify-group`, `burst-test`, `soak`, `watch`) and the documents. Together the two parts form the commissioning tool of epic 028, split under C-143 (a reference to epic 028 means both parts).

## Background

**Product frame.** Hadronyche Medianets are wired, isolated LANs whose only traffic is this runtime's. Modules exchange *slices* — all content of one stream for one stretch of media time — addressed by *position* on a domain-wide timeline. Linux hosts are the backbone (clock holder, elections, conformance, **commissioning**); macOS and Windows machines are edges; embedded devices are followers. IP is **IPv4 only** in v1, multicast with TTL 1 (C-100).

**Boundary `[decision]`.** The runtime owns *when and whether*; module code owns *what*; the **operator owns how much** latency and capacity to spend. Operator policy is: the audition offset A per presentation group; the required E per group; strict mode; per-input alignment opt-out; pacing override; trunk capacities; the domain id. This tool is how the operator sets those knowingly. Strict mode now has a defined meaning: it requires real-time scheduling on the data and clock threads and locked memory; restricting CPU idle states stays best-effort and is stamped (C-127); a capability that is unverified is treated as absent and refused (C-128). Strict mode is hosted-only: a device stamps real-time scheduling and memory lock as present by construction (C-147). The commissioning configuration sets strict mode, per-input alignment opt-out and pacing override (C-165).

**Recommended configuration.** Wired, isolated LAN with no internet traffic. A single non-blocking switch is the simple case: every link is an endpoint link, so the runtime's own online endpoint admission is complete. With several switches, **trunk** links are invisible to endpoints.

**Where the code and outputs live.** The tool is a binary in the `hadronyche-tools` crate in the design set's repository (C-133), created by epic 028a. Measured results this part produces (capture hardware, switch-family settings, the C-91 value) are reports in `doc/design/reports/`, and any constant goes into `doc/design/02-constants.md` first (C-130). Supported switch families and reference hardware are proposed by the implementing team (switches in P7, that is in this part), approved by the product owner and recorded in the constants table (C-172). Operator checklists and the commissioning guide live in `doc/operations/`; certificates are stored beside the collected stamps in the deployment's data directory (C-171). Nothing is written into the frozen POC tree.

**What epic 028a provides.** The binary `hadronyche-commission` with a stub per subcommand and the exit-code convention (028a-01); the capacity arithmetic module (028a-02); the configuration parser and writer (028a-03); `validate` with all its offline checks, including the per-direction trunk walk (028a-07) that `watch` reuses (028a-04 to 028a-10); the buffer-memory check that `propose-a --write` calls (028a-10, C-211); and the pure A proposal function implementing the commissioning rule (028a-11, C-148).

**What the tool does, and the rule behind each part.**

1. **Audition offset A — propose, and apply only inside a commissioning window.**
   - Every sink in a presentation group emits sample p at `emit(p) = T(p) + A` and submits it to hardware at `emit(p) − D` (D = that sink's total plumbing delay from hand-off to emission: driver buffer, resampler and converter, C-170).
   - A is **operator configuration**, one per presentation group (default group: the whole domain). **It has no default value** (C-55). Changing A is a domain-wide discontinuity.
   - A is also the skew budget cap: alignment rings are sized to A (C-96). A larger A therefore costs ring memory (about 370 KB per 16-member bundle at a 10 ms budget, C-27).
   - The tool proposes the **minimum feasible A** with the commissioning rule: the largest, over the group's sinks, of (maximum lateness + D + headroom), the headroom being the consumer rule C-52, the maximum lateness being the maximum since the connection went live, never the rolling 60 s figure of C-182 (C-148; the ladder harnesses use the same rule). The computation is 028a-11.
   - Lateness is what each consumer measures in its aligning state: 4 s of observation (C-50), offset = maximum observed plus headroom (C-51), headroom = the largest of 25 % of that maximum, one slice period, twice the published clock bound (C-52). The clock lock state and bound are published by the servo core (epic 008a) through the published time view, so this part depends on it (C-187).
   - A is also the ceiling of every fan-in's offset ratchet upstream (ratchet step one slice period, C-53, after a 10 s dwell, C-54). "Persistently late", which triggers a step, means at least one late slice in each of 10 consecutive 1 s windows (C-101). When the gap between offset and A is less than one slice period, the last step lands on A exactly (C-163). A ratchet step is a re-alignment like any other: a fan-in takes it at a position it announces one lead (C-43) ahead in its own output (C-215); a sink, which has no output, takes it at its own position one lead ahead (C-225). An input persistently late with its offset already at A enters the health state **Demoted** (C-109): treated as gapped, counted separately, cleared only by re-admission.
   - A fan-in outside any presentation group inherits the A of the downstream group it feeds (the largest if several), learned at admission; with no downstream group it needs an explicit budget in the configuration, or its aligned inputs are refused with reason NoSkewBudget (C-142, C-185).
   - **Changing A while inputs are live.** The receiver report carries each consumer's current A, its own or inherited, so a change propagates one hop per report (C-198); every fan-in that inherited the old A re-enters aligning with rings and ratchet ceiling resized, as the sinks do (C-186), at a position it picks itself one lead (C-43) ahead and announces in its own output; fan-ins at different depths switch at different, announced positions (C-208). A sink switches at its own position, one lead ahead, with nobody to announce it to (C-214). The tool picks no position: it supplies the value only.
   - **A against buffer memory (C-211, C-222).** Before applying a change of A (writing it to the configuration, `validate`, `propose-a --write`, `propose-a --apply`) the tool checks the declared buffer memory of every consumer that buffers to meet A, sinks included (C-222), against rings sized to the A it will hold (C-96; about 370 KB per 16-member bundle at 10 ms, C-27, that is channels × 96 000 × 4 bytes × A) and refuses a change that does not fit; the check is 028a-10. If such an A reaches a consumer anyway, it keeps the deepest ring it can hold as its ceiling, raises the cannot-meet-A alarm (C-174) and keeps its streams running (C-211, C-222); the alarm stays raised until a later change of A that fits, and the consumer's receiver report carries the A it was given, not the clamped value, so upstream modules size themselves to what the sinks need (C-216).
   - **Applying a commissioned change of A (C-224).** A commissioned change of a sink's own A reaches the sink through the tool, inside a declared commissioning window (C-153): the tool validates buffer memory first (C-211, 028a-10) and then announces the new A to the group's members. `propose-a --apply` does this; outside a window it refuses. Each sink then switches at its own position (C-214) and the change travels upstream in the receiver reports (C-198, C-208).
   - Measuring lateness needs the sinks to run, and they cannot run without an A. `propose-a` therefore measures under a **provisional A** the operator configures generously; a measurement in which any input reaches that ceiling or is Demoted is invalid and the tool asks for a larger provisional A. Changing the provisional A of running sinks is itself a commissioned change of A, applied inside a window (C-224); the measurement that follows is taken after the window closes, since lateness figures taken inside one are unqualified (C-178).
   - Typical D: Linux about 1 ms; macOS a few ms; Windows 6 to 20 ms (C-81). A group containing a Windows edge needs an A of the order of 10 to 25 ms.

2. **Trunk alarms — post hoc.**
   - **The runtime never computes trunk feasibility.** Trunk capacities are **declared** per link in the commissioning configuration, and a declared capacity is **per direction** (C-117).
   - The offline validation against the declared trunks is `validate` (028a-07).
   - After deployment the tool alarms post hoc from the regime stamps (observed rates per link and direction versus declared).
   - Endpoint port admission stays online and dynamic in the runtime.

3. **Capacity arithmetic** the tool uses (module from 028a-02):
   - One sample rate on the wire: 96 kHz, the domain rate (C-01). Edge hardware at 48 kHz converts 2:1 at the edge (C-80); a resampler node exists only inside an edge module, only for 2:1 and 1:2 (C-105, C-134), and its delay is part of that edge's D (C-134, C-170). The arithmetic never sees another rate.
   - Default stream: 6 channels (C-04), 48 frames = 0.5 ms (C-02), 4-byte samples (C-03): 192 bytes per channel per slice, 1 152 bytes of audio per packet, no per-channel id byte (the channel map is in the manifest, C-04). About 1 320 bytes per packet on the wire including all Ethernet overhead (C-20), 2 000 packets/s, about **21.1 Mbit/s per stream, about 3.5 Mbit/s per channel** (C-21).
   - Per source: 24 channels = 4 streams = 84 Mbit/s = 8 000 packets/s; 48 = 8 streams = 169 Mbit/s = 16 000 packets/s; 96 = 16 streams = 338 Mbit/s = 32 000 packets/s (C-22).
   - **Admission ceiling 70 % of the link rate** (C-23).
   - **GbE port wall: about 198 channel-copies** (8 × 24, 4 × 48 or 2 × 96 channels) (C-24). **Any port carrying more runs 10 GbE** (C-25). Multicast fan-out is not available in v1.
   - A 100 Mbit device port holds about 19 channels (C-26).
   - The L1 two-bundle rig (C-92): one Linux consumer on one GbE port aligns 2 × 96 channels (32 streams, 64 000 packets/s, 676 Mbit/s).
   - Controllers: a bundle source's controller member counts towards the 32 members of C-08, so a source with controllers has at most 31 audio members, 186 channels (C-209). A controller stream costs one packet per slice of (headers up to the 100-byte cap + controller bytes per slice + 66 bytes of Ethernet, IP and UDP overhead), at 2 000 packets/s (C-219), the figure admission uses too; `watch` costs observed controller packets at that size.

4. **Scale.** At most **64 active modules** per medianet (C-34), which also bounds followers per holder at 63 (C-114) and sizes every module's peer map at 63 entries, a module holding no entry for itself (C-217); at least one holder-capable (Linux) node. `validate` (028a-05) refuses configurations above it; the commissioning guide states it.

5. **Group-E certification.**
   - Each sink publishes E = 99.9th percentile of |actual emission − (T(p) + A)| over a one-hour run, maximum beside it (C-73). Targets: Linux reference sink 50 µs (C-70); macOS 100 µs (C-71); Windows WASAPI exclusive 1 ms (C-72).
   - A presentation group may carry a **required E**; the runtime refuses a sink whose E exceeds it. Only the commissioned state gives a numeric E; uncertified and self-monitored sinks declare E as unknown (C-140). A sink with unknown E is refused with reason RequiredEExceeded from any group that sets a required E and admitted to groups that set none (C-103). **The tool certifies membership**: it runs the on-site part of the measurement and records it.
   - E has a self-monitored part (clock bound + rate tracking) and a part needing external measurement (the uncertainty of D). Budget split: Linux 20 µs clock + 20 µs tracking + 10 µs uncertainty of D (C-70); macOS 40 + 40 + 20 µs and Windows 100 + 100 + 800 µs (proposals, C-150). Pass criteria use the platform's target E, never the E measured in the same run (C-149). L2 and L3 test parameters follow C-166 (restart spread of D is max − min; sample tolerances against the median of the first 60 s; measurement window after a restart 60 s; a one-sample slip passes on Linux and is reported as a slip event). The tool drives the external measurement: a marker loop for one sink (the L2 procedure) and a two-channel capture for a pair (the L3 procedure; pass = the 99.9th percentile of absolute skew at most the sum of the two sinks' E values, for 1 hour and across restarts of either, maximum reported beside it, C-79).
   - D must be repeatable across restarts: Linux at most 25 µs, macOS at most 50 µs, Windows at most 0.5 ms over 20 restarts (C-74); an embedded device declares its own restart spread, measured at L3 (C-191). "Both stamps" in a certification record are the regime stamps of the sink and of the holder it followed (C-191). Where a no-step or recovery tolerance is applied to a pair of different sinks, the larger of the two sinks' tolerances is used and both sinks' figures are reported beside the verdict (C-203).
   - A commissioned sink whose clock becomes unlocked stays commissioned: its alignment claim is suspended and does not count towards a group's required E until the clock is locked again, then resumes without re-commissioning (C-180).
   - Combinations of OS build, driver and audio device outside the reference list are recorded as *unverified*. Reference audio hardware is proposed after P0 and recorded in the constants table (C-172); supported OS versions are set after the receive-stamp probe task 001 reports (C-138).

6. **Per-OS checklists (laptop edges).** Trust statement: "trusted segment per the recommended configuration; Windows and macOS edges are best-effort members of a weaker segment." Baseline: a **dedicated medianet NIC**, OS **discovery chatter suppressed**, **firewall scoped to medianet ports**. Because the runtime uses IPv4 only (C-100), any IPv6 traffic on the medianet interface is foreign. Items the checklists must cover `[memory]`, to be confirmed by tasks 021 and 022:
   - macOS: pin to the medianet interface (Wi-Fi is default-routed); grant the local-network permission; prevent sleep (sleep is a departure: the edge resets both timebase loops and returns through normal admission, C-124); exclude aggregate, Bluetooth and network audio devices; silence discovery services on the medianet interface.
   - Windows: allow inbound UDP in the firewall for the medianet ports; exclusive-mode access to the audio device (other software must release it; "the interface is held" means another process has it open so it cannot be opened in the required mode, C-175); DSCP policy if marking is wanted; prevent sleep (C-124) and power throttling; receive buffer size; silence discovery services on the medianet interface.
   - Linux: privileges for real-time scheduling and memory lock (required by strict mode, C-127) and `/dev/cpu_dma_latency` (best-effort, stamped, C-127); kernel preemption model recorded.
   - The checklists and the guide are stored in `doc/operations/` (C-171).

7. **NIC and switch checks.**
   - **Interrupt coalescing** biases software receive stamps on every platform: disable it on medianet interfaces; the tool checks and records the state. Also check energy-efficient Ethernet. The receive-timestamp source of each module (kernel, userspace, mac-hardware, interrupt, C-131) is reported with it.
   - **Capabilities.** Each capability is stamped in one of four states: present, absent, unverified, not requested (C-129). A *capability gap* is a capability in state absent or unverified; "not requested" is a deliberate configuration choice and is reported for information only. On a node in strict mode, an absent or unverified real-time scheduling or memory-lock capability is a refusal-level finding (C-127, C-128). A module whose thread layout's seqlock safety depends on a CPU pin that failed or is unverified refuses to start in every mode (C-177, C-201), so it shows in `survey` as a missing module, not as a capability gap. The control-isolation capability is present on hosted platforms by construction and absent or unverified on a device unless the implementer shows a bound (C-161).
   - **Switch QoS:** three DSCP classes — sync CS6 (48), media and one-way probes EF (46), control CS5 (40) (C-13). Marking is verified by the receiving peer and reported in its regime stamp: media DSCP per connection (C-47), sync DSCP observed by the holder on each follower's requests, control DSCP observed by every module on each peer's hellos (C-152); on an unmanaged switch marking does nothing, and the tool says so.
   - **Burst test:** sources fire once per 0.5 ms slice; two 96-channel bundles arriving at one port are 32 packets (about 42 KB) per slice. The runtime spreads packets over at most 25 % of the slice (C-14) with a per-source phase offset; phase offset plus spread stay inside the slice period (C-155). The tool runs a burst test and reports drops.
   - **Path MTU:** every connection probes at admission with a probe pair sent at the intended media packet size (C-116); the fallback is 1 280 bytes (C-06), that is 1 252 bytes of UDP payload over IPv4 (C-100). The tool lists connections not at the interface MTU.
   - **Loss floor:** expected about 1.1e-8 per default packet (about 1 320 bytes on the wire) at a bit error rate of 1e-12, one loss per stream per link about every 13 hours at 2 000 packets/s (C-90) `[memory]` (re-tagged `[standard]` once the citation is checked, C-132). The **loss soak** runs 24 hours at the two-bundle load (64 000 packets/s, about 5.5e9 packets); its statistic is aggregate loss over all streams, where the floor predicts about 58 losses (C-118). The alarm threshold (C-91) is set from clean-network loss measured at L1: 10 × the measured clean-wire loss (proposal, C-167). Loss above it is a cable-health alarm. Soak loss above 10 × the published floor (C-90), about 580 losses in the 24-hour soak, reopens the redundancy decision; between 1 × and 10 × it is recorded and investigated as a cabling or host problem and does not (C-179).

8. **Domain.** Domain id is 16 bits, operator-configured; 0 means unconfigured (C-11) and strict mode refuses to start with it. `validate` (028a-04) assigns and checks it; `survey` reports a strict-mode module on domain 0.

9. **Read-only outside a commissioning window.** The tool may drive test traffic (burst test, soak, the marker loop, restarts for the D spread) only inside a declared **commissioning window** that every module stamps; outside it, it is read-only: it reads stamps and writes configuration (C-107). Inside it the tool also announces a commissioned change of A (C-224). Window life cycle (C-153): the tool announces the window on the control group with an expiry time; modules stamp it while it is open; it closes at expiry or on explicit close. While a window is open, ordinary production measurements (latency, loss, alignment figures in stamps) are unqualified; the tool's own measurements (D, restart spread, group certification, soak) are valid commissioning results, each recorded with the window it was taken in (C-178). Before driving anything the tool checks from the stamps that every module in scope shows the window open, with enough time left before expiry for the run.

10. **Foreign multicast `[decision]`.** Stamps cannot show traffic that is not the runtime's, so the clean-survey check (AC-9) observes the medianet interface of the survey host passively, receive-only. Anything that is not this runtime's IPv4 traffic, including all IPv6, is foreign (C-100).

11. **Tests without privilege.** Tests that need a privilege (live packet capture, changing NIC settings) run in the separate privileged nightly job; per-change CI runs unprivileged, from recorded fixtures (C-146).

**Inputs the tool consumes at run time.** Regime stamps only. A regime stamp is a wire object every module publishes (identity, capability states, network, clock, alignment, platform, drops, injection). It travels as a dedicated control message split into sections that each fit the control message bound (C-17); it is multicast to the control group on any regime change and refreshed every 10 s, and a unicast request gives an immediate fetch; the hello carries only a stamp version number (C-18). Producer and consumer each publish per-connection summary counters in their own stamp (C-47, completed by C-159): received, late, missing, marked gap, other-epoch, too-early, duplicates, incomplete reassemblies, demoted rounds, interrupted events, dead, and the observed DSCP; lateness is published as the 50th, 99th and 99.9th percentiles and the maximum (C-160), over a rolling 60 s window, with the maximum since the connection went live beside them; reclaimable latency and the cannot-meet-A alarm use the same window (C-182). The runtime raises a connection alarm on refusal, interrupted, dead, demoted, cannot-meet-A and control-degraded (C-173); "cannot meet A" means maximum lateness + D + headroom exceeds A in each of 10 consecutive 1 s windows (C-174). Receiver reports are unicast to the producer and not visible to this tool, and there is no query message for them (C-47). Counters follow these rules: an absent slice is counted missing at the deadline and reclassified as late if it arrives while still within the ring span (missing −1, late +1, C-108); session numbers are per stream, assigned by the source and bumped on restart and timeline epoch change (C-19). A colliding module id is recognised by two instance nonces; third parties quarantine it until only one nonce has been seen for 3 s (C-46).

**Configuration shape.** The configuration format is epic 028a's (028a-03): besides the domain, trunks, groups and connections it declares nodes (name, OS, endpoint port rate, the switch they attach to), modules (name, node, output channel counts, and for sinks the declared E or none), and for each trunk the two switches it joins (needed for per-direction sums, C-117). A group's `required_e_us` is optional (C-103); its `a_ms` is mandatory (C-55). Operator policy (C-165): strict mode per hosted node (C-147), per-input alignment opt-out per connection, pacing override per module (C-14, C-155); and an explicit skew budget for a fan-in that feeds no presentation group (C-142). An aligning module may declare its buffer memory (`buffer_kb`, C-211). The default group (the whole domain) is written as a `[[group]]` named `default` with no `members` list: it holds every sink not listed in another group, and its `a_ms` is required like any other. `propose-a --write` writes `a_ms` through the writer of 028a-03; `survey --config`, `certify-group` and `watch --config` read it.

| `propose-a <group>` | Read-only: observes the group's sinks aligning under a provisional A, collects lateness (the since-live maximum, C-148) and D, proposes minimum feasible A with its breakdown per sink; `--write` refuses an A that does not fit declared buffer memory, sinks included (C-211, C-222); `--apply`, inside a commissioning window only, runs the same check and then announces the new A to the group's members (C-224) |

| `certify-group <group>` | Checks every member's E against the required E; inside a commissioning window, drives pairwise skew measurement where a capture device is available; writes the membership certificate |

## Acceptance criteria

Acceptance criterion ids are those of epic 028; the others (AC-1, AC-2, AC-3, AC-5) belong to epic 028a.

1. **AC-4 A proposal.** On the L1 two-bundle rig (one Linux consumer on one GbE port aligning 2 × 96 channels, C-92), the proposed A, once configured, yields zero late slices for 1 hour (runtime AC-14); the proposal shows per sink: lateness, D, headroom (C-148).
2. **AC-6 Certification.** `certify-sink` on the Linux reference sink reproduces the L2 figures within 20 %; `certify-group` on the L3 rig reproduces the skew result.
3. **AC-7 Survey.** Coalescing enabled on a medianet NIC, a path MTU below the interface MTU, an unverified platform combination, and a capability in state absent or unverified each appear as a named finding.
4. **AC-8 Post-hoc alarm.** With a trunk declared smaller than its observed load in one direction, `watch` raises a named alarm from the stamps.
5. **AC-9 Checklists.** Following each OS checklist on a fresh machine yields a clean `survey` (no foreign multicast, including any IPv6, observed on the medianet interface for 10 minutes).
6. **AC-10 Read-only outside a commissioning window.** Outside a commissioning window stamped by every module, the tool only reads stamps and writes configuration; `burst-test`, `soak` and `certify-sink` refuse to start; inside the window it drives only test traffic (C-107) and the announcement of a commissioned change of A (C-224). The only message it sends outside a window, besides stamp fetch requests, is the window announcement or close itself (C-153).
7. **AC-11 A against buffer memory (`propose-a` half).** `propose-a --write` refuses to write an A that gives an aligning module rings larger than its declared buffer memory (channels × 96 000 × 4 bytes × A, C-27, C-96), naming the module (C-211); a sink is checked like a fan-in (C-222). The `validate` half, and the check itself, are epic 028a's (028a-10).
8. **AC-12 Applying a commissioned A.** `propose-a --apply` outside a commissioning window refuses and sends nothing; inside one it refuses an A that fails the buffer-memory check (C-211, C-222) and otherwise announces the new A to the group's members, after which every sink's stamp shows the new A and its receiver reports carry it upstream (C-224, C-214, C-198).
