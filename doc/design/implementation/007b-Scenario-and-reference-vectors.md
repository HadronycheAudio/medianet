# 007b — Scenario and reference vectors

**Phase:** P1 · **Scope:** L (24 tickets, about 37.5 days) · **Depends on:** 002, 003, 004, 005, 006, 007a · **Blocks:** 009, 010, 011, 012, 013, 014, 025, 026

## Goal

Produce the second half of the implementation-agnostic conformance data for the protocol: scenario vectors for the control state machines and the timeline, the POC transport scenario and gap-semantics vectors, exact-tier reference data for the reference echo and mixer, the state-machine fuzz targets and the CI budget job, the full conformance run, and `conformance.md`. Any implementation, hosted or embedded, is judged against these. Epic 007 was split under C-143; this part is 007b and depends on 007a (wire vectors and harness). A reference to "epic 007" means both parts.

## Background

**Product frame.** Hadronyche Medianets are wired, isolated LANs whose only traffic is this runtime's. Modules discover each other, agree on one clock holder and exchange *slices* addressed by *position* on a domain-wide timeline. Linux hosts are the backbone; macOS and Windows machines are edges; embedded devices are followers. Two profiles (hosted and embedded) are built from one `no_std` core crate; conformance vectors are how the specification is shown to be complete and how the two profiles are shown to agree.

**Evidence tags.** The design set defines six tags: `[code]` read in the POC · `[measured]` observed · `[kernel-doc]` · `[memory]` · `[standard]` a figure cited from a named, published standard with the clause, which replaces `[memory]` once the citation is checked (C-132) · `[decision]` design choice (definitions in `00-context.md`). This part uses `[code]`, `[measured]` and `[decision]`.

**Constants.** Every number below comes from the constants table `doc/design/02-constants.md` and is cited by its C-id; if a value here differs from the table, the table wins. Epic criteria keep the ids of the original epic 007 (007-AC1 to 007-AC8); this part carries 007-AC3, 007-AC5, 007-AC6 and 007-AC7, and 007a carries the others. System criteria keep their system ids (AC-1, AC-7, AC-25).

**What 007a provides.** The crate `hadronyche-vectors` with the schemas of all six vector kinds (each file with a mandatory specification version and unique id) and the `no_std` reader; the `UnderTest` runner trait with its observation extension (drop counters, named events including alarms, state digest, local domain and pinned sources) and the drivers; the generator `gen` and its table-driven codec; all wire vectors, valid and invalid; and the parser fuzz targets. Code lives in the design set's repository: harness and tool binaries in `hadronyche-tools`, protocol types in `hadronyche-core` (C-133); `conformance.md` in `doc/design/spec/`, results in `doc/design/reports/` (C-130). On a real implementation the driver may reach the test-only hooks of C-120 (force a module id and nonce, force a stream onto a timeline epoch, send a raw packet on a media or control socket).

### The verification tiers `[decision]`

| Tier | What it proves | Mechanism |
|---|---|---|
| Transport integrity | Bytes delivered equal bytes sent, per slice | Slice checksum |
| **Protocol conformance** | Any implementation speaks the protocol | **Epic 007:** byte-level vectors both directions including malformed inputs (007a); state-machine scenario vectors (this part); fuzzing (parser targets in 007a, state-machine targets and CI budget here) |
| Reference modules | Kept permanently | Reference sender, echo and mixer; bit-exact by construction |
| Exact tier | exact-class modules | Record input slices and output hashes; replay the same code offline; compare |
| Tolerance tier | bounded-class modules | Analyzer windows and per-voice projections with stated epsilons |

### Rules the scenario vectors must cover `[decision]`

*Defaults.* Domain rate 96 000 Hz, the only rate on the wire (C-01); slice 48 frames, 0.5 ms (C-02); 6 channels per stream (C-04); at most 32 members per bundle, the controller member included: a bundle source's controllers always ride in their own member stream, so a source with controllers has at most 31 audio members (C-08, C-205, C-209); 256 streams per source (C-09), 64 modules in the map (C-34). A multi-packet slice is an explicit, stamped regime (C-05).

*Control scenarios.*
- Discovery: map with 64 entries and a 65th arrival (commissioning refuses more than 64, C-34; at runtime the 65th is stopped from joining with ModuleCap, C-185); VersionMismatch and NameTaken are also raised at discovery and stop a module joining (C-185); hello every 1 s (C-30); hello expiry at 3 s for non-live peers only (C-31); id collision detected within one hello period, later joiner redraws, third parties quarantine the colliding id until only one instance nonce has been seen for 3 s (C-46); a hello with domain 0 is ignored and counted, not refused (C-173).
- Election and clock holder: election on 1.5 s of sync-reply silence (C-37), window 400 ms (C-33), never on hello expiry while replies flow; no rotation; merge by higher election epoch; a holder-eligible module whose time is usable (Locked, or in holdover with its alignment claim not lapsed, C-65, C-169) may take over, with frequency continuity and the timeline epoch kept; only when no candidate has usable time does the holder-eligible candidate with the lowest module id win and bump the timeline epoch (C-113, C-213). A holder serves at most 64 followers and refuses the excess with a named event (C-35; its falsifier is owned by L1, task 019); with at most 64 modules a holder has at most 63 real followers, so the 64-follower load and the refusal of a 65th are tested with synthetic followers (C-114, system AC-25). Accepted sync request rate is 10 to 200 per second (C-112); requests beyond 200 per second from one follower are dropped before any work is done and counted per follower in the holder's stamp (C-204). Holder stall: a divergence above 2 ms (C-67) between the monotonic clock and a clock that keeps running through suspend bumps the timeline epoch (C-136). The holdover entry delay is at most 1.5 s (C-37), a hard limit, so a follower is always in holdover with a growing bound when it calls an election; the value within that limit is pending simulation (epic 008b, which reports a finding if no value at or below 1.5 s works); scenarios state the delay they use (C-195). After the holdover claim lapses (about 25 s, C-65) the clock is Unlocked with time unusable (C-162); a device whose E is unknown takes 2 × C-62 (50 µs) as the reference and stops claiming alignment when its published bound exceeds it (C-169). A commissioned sink whose clock is unlocked stays commissioned; its alignment claim is suspended and does not count towards a group's required E until it locks again, then resumes without re-commissioning (C-180).
- Admission: two-sided, with each of the 18 refusal reasons (C-185): the 16 of C-173 plus ControlDegraded (the target's housekeeping has stopped restarting, C-139; answered by the housekeeping supervisor, which keeps a minimal refusal path) and NoSkewBudget; VersionMismatch, NameTaken and ModuleCap among them are raised at discovery, not at admission (C-185). Only a commissioned sink has a numeric E; uncertified and self-monitored sinks declare E unknown (C-140) and are refused with RequiredEExceeded from any presentation group that sets a required E and admitted to groups that set none (C-103). PathMtuTooSmall applies only when the probe at the 1 280-byte fallback also fails; ForeignDomain is for a different non-zero domain; BadMemberList covers an unknown or duplicate member or more than 32 members (C-173). A fan-in outside any presentation group inherits the A of the downstream group it feeds, the largest if several; with none it needs an explicit budget, or its aligned inputs are refused with NoSkewBudget (C-142, C-185). The admission ceiling is 70 % of the link rate (C-23) and declared trunk capacity is per direction (C-117). Pending has no timeout: it persists until the target appears or the operator cancels, and is shown as unsatisfied (C-45); only Live is satisfied (C-154).
- Connection states: Requested, Pending, Refused, Admitted, Locking, Aligning, Live, Interrupted, Dead, Ended. Interrupted after 8 consecutive missed slices (C-38), where only a slice absent at the deadline (missing, or arriving late) counts as a miss and a marked gap or a slice on another timeline epoch resets the count (C-102). Dead after 2 s (C-39), counted from the last slice received with content or a marked gap (C-111); an other-epoch slice also restarts the dead clock and has its own counter (C-135). Producer stop after 2 s without receiver reports (C-41); receiver report every 100 ms per bundle (C-40), not multicast (C-47). The liveness of a sink-only device is judged by the producer timeout only (C-168). Laptop edge sleep is a departure: the edge returns through normal admission, Locking then Aligning (C-124).
- Alignment health: at the deadline an absent slice is counted missing; if it arrives later while its position is still within the ring span it is reclassified as late (missing −1, late +1) and discarded (C-108); rings are sized to the presentation group's A (C-96). "Persistently late" is at least one late slice in each of 10 consecutive 1 s windows (C-101) and triggers a ratchet step of one slice period, with A as ceiling (C-53, C-54); when the gap to A is less than one slice period the offset steps to A exactly (C-163). A ratchet step is a re-alignment like any other: it takes effect at a position the fan-in announces one lead (C-43) ahead in its own output, never silently on the next round (C-215). An input persistently late with the offset already at A enters the health state Demoted: treated as gapped, counted separately, cleared only by re-admission (C-109).
- A changed while inputs are live: every fan-in that inherited the old A (C-142) re-enters aligning at an announced position, with rings and ratchet ceiling resized, as the sinks do (C-186). The changed A travels upstream in the receiver report (C-40), which carries the consumer's current A, its own or the one it inherited; the change propagates one hop per report, on the data plane (C-198). Each fan-in that learns of the change picks its own position one lead (C-43) ahead and announces it in its own output, so fan-ins at different depths switch at different, announced positions (C-208). A fan-in that cannot hold a ring for the new A keeps the deepest ring it can hold as its ceiling, raises the cannot-meet-A alarm and keeps its streams running; the commissioning tool's check against declared buffer memory is the tool's (C-211). The alarm stays raised until a later change of A that fits, and the clamped fan-in's receiver report carries the A it was given, not the clamped value, so upstream modules size themselves to what the sinks need (C-216).
- Connection alarms: raised on refusal, interrupted, dead, demoted, cannot-meet-A and control-degraded (C-173); cannot meet A is maximum lateness + D + headroom above A in each of 10 consecutive 1 s windows (C-174), with the maximum lateness taken over a rolling 60 s window (C-182). Control-degraded comes from the housekeeping restart policy (C-139) of epic 015 (C-144).
- Multi-packet reassembly: an arrival-driven input has a reassembly deadline of 2 slice periods (C-15); an aligned input uses the consumer's own deadline for that position (C-110).
- Regime stamp distribution: multicast on change, refresh every 10 s, immediate answer to a unicast request (C-18). The stamp carries the per-connection counters received, late, missing, marked gap, other-epoch, too-early, duplicates, incomplete reassemblies, demoted rounds, interrupted events, dead (C-47, C-159), the observed DSCP (C-47, C-152) and the lateness percentiles (C-160); the percentiles and the reclaimable latency (C-157) use a rolling 60 s window, with the maximum since the connection went live beside them (C-182). The message is defined by epic 013 and sent by epic 015 (C-144).
- Commissioning window: announced by the tool on the control group with an expiry time; modules stamp it while open; it closes at expiry or on explicit close (C-107, C-153). While a window is open, ordinary production measurements (latency, loss, alignment figures in stamps) are unqualified; the commissioning tool's own measurements (D, restart spread, group certification, soak) are valid commissioning results, each recorded with the window it was taken in (C-178).

*Timeline scenarios.* Position = (network time − epoch origin) × rate, with rate the domain rate 96 000 Hz (C-01); affine per epoch, never extrapolated; announcement lead 64 slices (C-43), re-issued every 16 slices until the named position passes, in every bundle member (C-44); the session number is bumped on an epoch change (C-19); a fan-in treats an other-epoch input as a gap.

*Content on a gap.* Transport state: the last known state is held and the playhead advanced as that state dictates: a stopped transport's playhead does not advance (C-200), a playing one moves on at its tempo; the output is marked degraded (C-141). Before any transport state has arrived the state is stopped, playhead at zero, default tempo (C-184) of 120 beats per minute (C-199). A dense controller with no prior value uses the initial value declared in the manifest, default 0 (C-158); the reference dense controller is the mixer's volume (C-192). A bundle source's controllers ride in their own member stream, so a gap there gaps only the controllers; a single-stream source may always put its controllers in a second stream and must when headers plus controllers exceed the 100-byte cap (C-137); it may share the audio packet while they fit, and the compiler checks this from the manifest (C-181 revised, C-205).

*Reference modules.* Structural latency L is always a whole number of domain-rate samples (C-105). The degraded flag follows the content: stamps denote content position; while a module processes input position p it emits the output stamped p − L, whose content came from input position p − L, and that output is degraded if the input at p − L was gapped (C-122). Reference vectors are bit-exact across x86-64 and 64-bit ARM (C-151).

*Fuzzing.* Each parser is fuzzed 60 s on every change and 1 hour nightly; the corpus is kept (C-95); state-machine targets run under the same budget. The fuzzing tool is the implementing team's choice (C-192). Per-input bound: linear in packet length, at most 10 µs per packet (C-164, pending L1). Per-change CI is unprivileged; nothing in this part needs the privileged nightly job (C-146).

### The POC as a source of vectors `[code]`

The frozen proof of concept (`/home/dorian/workspace/hadropoc`, tag `poc-baseline` from task 003) contributes two things, and only after the archaeology of task 002 has cleared its instrument bugs:

- its **transport scenario test** (`transport.rs:864-947`: a conductor and a follower run a scripted scenario of tempo, time-signature, stop/continue and time-code changes, and the follower's clicks must equal the conductor's expected clicks sample for sample, for block sizes 48 and 7). This becomes a conformance vector for read-only transport state semantics;
- its **test instrument**: the add/multiply-only `sine()` (`music.rs:263`), the fixed-point voice renderer (`music.rs:382`) and the mix functions (`audio.rs:217`, `audio.rs:237`), whose outputs for scripted inputs become exact-tier reference data for the reference echo and mixer. One hole to avoid: the POC's fixed-point sine table is built with libm on each machine (`music.rs:311`); the vectors must ship the table as data.

Exact-tier gap baseline to encode: windows of 1 024 samples touched by loss or by a degraded slice are excluded and counted; the reference mixer treats a missing input as zero and marks its output slice degraded.

## Deliverables

1. In crate `hadronyche-vectors` (at the workspace root, C-192; formats and reader from 007a):
   - `vectors/control/*.json`: scenario vectors as ordered lists of (time, input) → expected (outputs, events, resulting state), for every control state machine of epic 005 and for the behaviours listed under *Control scenarios*;
   - `vectors/timeline/*.json`: position/time conversions and epoch-switch scenarios;
   - `vectors/transport/*.json`: the POC transport scenario re-expressed against the new wire format, and the gap-semantics vectors for transport state and dense controllers (C-141, C-158);
   - `vectors/reference/*`: scripted inputs and expected output hashes for the reference echo and mixer, in both f32 and Q1.31, including runs with gaps. The hash algorithm and the input script format are chosen by this part and recorded in `conformance.md`.
2. A mechanical transition-coverage check over all scenario vectors.
3. Fuzz targets for the state machines in the `hadronyche-tools` crate (C-133), seeded from the scenario vectors, and the CI jobs applying the C-95 budget to every parser and state-machine target.
4. One CI entry point running all vectors of both parts against an `UnderTest`, wired in this epic to an adapter around the generator's own codec.
5. `doc/design/spec/conformance.md` (in the design set's repository, beside the constants table `doc/design/02-constants.md`; C-130): what conformance means, how to run the vectors, how a vector is added. Results such as the cross-machine hash runs go to `doc/design/reports/` (C-130).

## Acceptance criteria

1. **007-AC3.** Every transition row of every control state machine is exercised by at least one scenario vector; coverage is checked mechanically.
2. **007-AC5.** The transport scenario vector reproduces the POC result: clicks identical for block sizes 48 and 7.
3. **007-AC6.** Reference vectors pass on an x86-64 machine and a 64-bit ARM machine (C-151) with identical hashes, in both sample formats.
4. **007-AC7.** System criterion AC-1: 100 % of vectors of both parts pass in both directions, malformed cases included; zero parser panics and zero hangs within the fuzz budget (C-95). No implementation under test exists in this epic (the core is epics 009 to 014), so here the criterion is met against an adapter around the generator's own codec, and the same run is the entry point those epics must pass.
