## Why row (b) reads "not the same criteria"

The script prints `FAIL Hand-off: …` on the red-phase tree too (checked by
hand: exported `doc/` of 7221624 with the current script, `WIRE_MD` and
`WIRE_TOML` set; the FAIL labels it prints are AC1, AC2, AC5, AC6, AC7,
Behaviour, DoD, Hand-off, Settled — the same nine the port reports). The
harness reads criteria with `^FAIL ([A-Za-z]+ ?[0-9]*):`, which stops at the
hyphen of `Hand-off`, so it lists eight for the script. Row (b) cannot be
classified; the fix is the harness's label pattern (library), not the port.
The same limit makes the two denial rows above show one criterion more for
the port, and the `hand_off_denial_no_012_01` row (the script's only FAIL
line is Hand-off) read as a crash; both kinds are excused in `KNOWN` with
that reason. Every other row of (a), (c) and (d) is the same.
